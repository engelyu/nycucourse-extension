# 選課規劃頁：整合查詢與正式選課、本機課程狀態

日期：2026-09-19
狀態：設計已確認，待實作
前一版：`2026-09-19-planner-free-slots-design.md`

## 目的

在選課規劃頁找到課之後，不用切到選課頁就能**查詢**能不能選、**加選／登記**。每門課目前的狀態（在預排、登記中、已選上）記在本機，直接顯示在卡片和格子上，取代「排除」勾選框。

## 使用者確認過的決定

| 項目 | 決定 |
|---|---|
| 結果卡片 | 「加入預排」「查詢」；查詢後每種採計方式有「加選」或「登記」 |
| 不在預排的課要加選／登記 | 先自動用那一種採計方式加入預排，再查詢、確認、送出（和官方選課網同樣順序） |
| 課程狀態 | 本機記錄；**主動更新**（按鈕）與**順便更新**（加入、加選、登記成功後自動重讀）兩種 |
| 篩選 | 拿掉「學分」與「排除已在正式選課／預排」 |
| 格子配色 | 正式選上、登記中、在預排、私人行程各一色；私人行程用使用者在課表頁設的顏色 |
| 商店 | 暫停送審，功能完成後再送 |

## 1. 本機課程狀態

- 狀態來源沿用 `chrome.storage.local` 的 `schedule.sources`：`registered`（正式選課）與 `preregist`（預排），各有 `updatedAt`。不另建資料庫。
- `courseStatuses(schedule) -> Map<課號, { state, wishNo, label }>`：
  - `registered`：已選上，label「已選上」。
  - `wish`：登記中，label「登記中・第 N 志願」。
  - `preregist`：在預排、未登記，label「在預排・<採計方式>」。
  - 正式選課優先於預排。
- **主動更新**：頁首按鈕「從選課網更新狀態」，透過已開啟的選課網分頁送 `courses` 訊息，用 `withSyncedSources` 寫回。旁邊顯示「狀態更新於 M/D HH:MM」。讀不到時只提示原因，不清空。
- **順便更新**：加入預排、加選、登記成功後，自動再送一次 `courses` 並寫回。storage 一變，頁面上的卡片與格子就會跟著重畫。

## 2. 查詢與加選／登記

### 結果卡片

- 按鈕：`加入預排`（已在預排或已選上時不顯示）、`查詢`（已選上時不顯示）。
- 右上角的狀態標籤：`已選上`、`登記中・第 2 志願`、`在預排・選修`。

### 查詢

- **課已經在預排**：用預排記的採計方式查一次（`resolveRegInfo`，和選課頁相同）。結果只有一列。
- **課不在預排**：用 `findAttributionOptions` 找出所有採計方式，每一種都查一次（`reginfo`，參數是那種方式的選單，`category_type` 用那種方式的類別）。每一種一列。
- 每一列顯示：採計方式、`describeAvailability` 的結果（可加選／可登記（志願序）／不能選的原因原文、人數、衝堂）。可以選的那一列右邊有 `加選` 或 `登記`。

### 加選／登記

1. 課不在預排：先用這一列的採計方式加入預排（`setpreregist`，參數同加入預排）。失敗就停，顯示原因。
2. 開確認視窗（和選課頁同一個元件）：課名、老師與時間、人數、注意事項。需要志願序的課要選第幾志願，並列出各志願已填的課與登記人數。
3. 使用者按「送出加選」或「送出登記」才送 `setregist`。結果顯示在卡片上，例如「已登記第 2 志願」「加選成功」，或選課網的錯誤原文。
4. 成功後做順便更新。

### 安全

- 只有使用者在確認視窗按「送出加選」或「送出登記」才會送出。
- 不做退選；已選上的課不顯示加選或登記按鈕。

## 3. 共用確認視窗

- 從 `src/register.js` 抽出成 `src/reg-dialog.js`：`createRegisterDialog()` 會自己建立 `<dialog>`（沿用原本的 id：`confirm`、`confirm-title`、`confirm-body`、`wish-block`、`wish-options`、`confirm-error`、`btn-cancel`、`btn-submit`），提供 `open({ heading, detail, check, groups }) -> Promise<{ ok, message, wish } | null>`。
- `null` 代表取消。送出透過 `askCos({ type: 'register', params: registerParams(record, wish) })`。
- 樣式放 `src/reg-dialog.css`，選課頁與規劃頁都引用。
- 選課頁改用這個元件，行為不變；`register.html` 移除原本的 `<dialog>`。

## 4. 格子配色與篩選

- 佔用格子依狀態上色：
  - 正式選上：綠
  - 登記中：橘
  - 在預排：藍灰
  - 私人行程：使用者設的顏色（`schedule.manual[].color` 或覆寫顏色），沒設就用紫
- 同一格有多種時，依「正式選上 > 登記中 > 在預排 > 私人行程」取第一種，格子提示文字列出全部。
- 格子上方附圖例。
- 篩選拿掉「學分」「排除」兩組；`findCourses` 的相關參數保留不用。

## 5. 測試

單元測試：

- `courseStatuses`：正式選上、登記中、預排、正式選課優先、採計方式標籤。
- `occupiedKinds`：格子狀態分類與優先順序、私人行程顏色。

瀏覽器測試（假選課網）：

- 查詢：在預排的課一列、不在預排的課每種採計方式各一列、不能選時顯示原因。
- 不在預排的課按登記：先送 `setpreregist`，再開確認視窗；選志願後送 `setregist`（`wish` 正確）。按取消就不送 `setregist`。
- 成功後自動重讀，卡片變成「登記中・第 N 志願」，格子變成登記中的顏色。
- 「從選課網更新狀態」、讀不到時保留舊狀態。
- 已選上的課沒有加選或登記按鈕。
- 選課頁全部既有測試（確認視窗、志願序）照樣通過。
