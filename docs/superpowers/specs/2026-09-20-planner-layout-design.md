# 當期選課頁：左搜尋結果、右正式課表、可收起的篩選

日期：2026-09-20。接在 0.9.2（分支 `fix-reg-wish`）之後。

## 目的

現在的當期選課頁：
- 左欄是框選格子加上篩選。
- 右欄是搜尋結果。
- 沒有地方看「我現在排了哪些課」。

使用流程其實是「打開篩選設定好 → 關掉 → 邊看結果邊排課」。所以版面改成：
- **左欄**：搜尋結果，篩選收在一個按鈕裡。
- **右欄**：正式課表，顯示目前所有的課。同一節有很多堂時，格子往下撐高，全部列出。

## 使用者已決定

| 項目 | 決定 |
|---|---|
| 課表內容 | 全部狀態：已選上、已登記、在預排、私人行程，依狀態上色 |
| 篩選打開的位置 | 覆蓋在右欄課表上；左邊結果即時更新 |
| 同一格多堂課 | 做法 A：每一節各自列出，列高依最多堂數撐高 |
| 滑過左邊的課 | 右邊只把它的時段格子底色標亮，列高不變 |
| 點課表裡的課 | 看詳情、查詢／加選／登記、從預排移除（只限預排） |

### 頁首

- 保留 h1「當期選課」、「從選課網更新狀態」和更新時間。
- 移除原本「找空堂課程：框選想上課的時段…」的說明文字（改放在篩選面板的時段區塊）。

### 左欄：搜尋結果

**工具列**（固定在左欄頂端，捲動結果時不跟著捲走）：
- 關鍵字輸入框：從篩選移到這裡，因為最常改。
- 「篩選」按鈕：
  - 顯示已套用條件數，例如「篩選 (3)」。
  - 時段算一個條件，其他每個條件也各算一個；關鍵字不算，因為它就在旁邊。
  - `aria-expanded` 反映面板是否打開，`aria-controls` 指向面板。
- 排序下拉選單：從篩選移到這裡。

**工具列下方**：
- 已套用條件的 chip，可逐一 ×，加「清除全部篩選」（沿用現有 `#applied`）。
- 結果數與分組（完全落在內／部分重疊）、零結果建議、結果卡片：全部沿用現有 `results.js`。

### 篩選面板（覆蓋右欄）

- 打開時蓋住右欄課表，寬高與右欄相同，內容可捲動。
- 面板上方有標題「篩選」和關閉鈕 ✕。
- 由上到下四個區塊：
  1. **時段**：框選格子、兩個「帶入空堂」、「全部清除」、「復原」、已選幾格、操作說明。格子的格子內標記（已選上／已登記等）與圖例照舊。
  2. **比對方式**：完全落在內／部分重疊。
  3. **校區、類別**（含選項旁的結果數）。
  4. **系所**：多選系所挑選器。
- 關閉方式：
  - 按 ✕、按 Esc、再按一次「篩選」都可以。
  - 關閉後焦點回到「篩選」按鈕。
- 開著時左邊結果即時更新（現在就是即時篩選，不需要「套用」按鈕）。
- 開或關的狀態存在 storage `planner.filterOpen`，重開頁面維持。第一次使用（沒有存過）預設打開，因為一開始還沒選時段。

### 右欄：正式課表

**資料**：
- 來源是 `scheduleItems(schedule, ['registered', 'preregist'])` 加上私人行程。
- 已停修、使用者在課表頁隱藏的課不顯示，沿用 `scheduleItems` 現有行為。
- 狀態沿用 `lib/status.js` 的 kind：registered／wish／preregist／manual。

**顯示範圍**：
- 欄：星期一到五一定顯示；週六、週日有課才顯示。
- 列：節次 1–9 一定顯示；Y、Z、N、A–D 有課才顯示。
- 順序依 `PERIODS`。

**每一節（做法 A）**：
- 每個格子由上往下列出這一節的課。
- 列高 = 該列所有格子中最多的堂數，用 CSS grid，列高 `auto`。
- **同一天的位置固定**：
  - 同一天中，一堂課在它每一節的位置（第幾個）相同。
  - 用區間著色：該天的課依狀態優先序、開始節次、課號排序，逐一分配最小可用的位置號。一堂課在同一天的所有節次（包含不連續的，例如一 1 和一 5）用同一個位置號，這個號碼在它所有節次都必須空著。
  - 格子內某個位置沒有課時留空白佔位，讓同一堂課上下對齊。
- **同一格的排序**：依位置號。位置號是依狀態優先序（已選上 → 已登記 → 在預排 → 私人行程）分配的。
- **卡片內容**：
  - 連續節次的第一節：完整卡片，包含標記（✓／①／登／預）、課名（一行，超出用 …）、教室。
  - 同一段連續節次的後續節次：細條（約 6px 高），只有顏色，`title` 是課名。
  - 顏色：沿用 `KIND_COLORS`，私人行程用使用者設定的顏色。
  - 樣式：淺底加左側色條，和現在格子上的樣式一致。
- **衝堂提示**：
  - 同一格有 2 堂以上，且其中至少一堂是已選上或已登記，格子加紅框。
  - `title` 寫「衝堂：課名、課名」。
  - 全是預排或私人行程不加紅框。

**滑過預覽**：
- 滑過（或鍵盤聚焦）左邊一張結果卡片時，右邊把它的時段格子底色標亮，列高不變。
- 時段不在目前顯示範圍時（例如週六沒有其他課），課表上方顯示一行「另有：六 3–4」。
- 滑過右邊一張卡片時，同一堂課的所有卡片一起標亮。

**點卡片：詳情小卡**：
- 以 `<dialog>` 或 popover 開在卡片旁；窄視窗時置中。
- 內容：課號、課名、老師、時段與教室、狀態文字（沿用 `courseStatuses` 的 label）、採計方式（預排才有）、課程大綱連結。
- 動作依狀態不同：

| 狀態 | 動作 |
|---|---|
| 在預排 | 「查詢」：顯示各採計方式能不能選，可以直接加選或登記，流程與左邊結果卡片相同，共用 `queryCourse` 與確認視窗。「從預排移除」 |
| 已登記（有志願序） | 「查詢」後可以「改志願」 |
| 已登記（等分發）、已選上 | 只看詳情 |
| 私人行程 | 只看詳情，另有「到課表頁編輯」連結（開 `schedule.html`） |

- **永遠不提供**：退選、移除已選上或已登記的課。

**從預排移除**：
- 新的 content script 訊息 `removepreregist { cosId }`。
- 送出前先讀一次 `getregist`：
  - 讀取失敗，拒絕移除，回報「讀不到正式選課清單，先不移除」。
  - 課號在清單內（已選上或已登記），拒絕移除，回報「這門課已在正式選課，不能從這裡移除」。
- 兩項檢查都通過才呼叫 `deletepreregist`。
- 成功後：
  - 課表先移除這堂課，再照現有的順便更新流程同步。
  - 頁面底部顯示提示「已從預排移除 課名・復原」，10 秒後消失。
- 按「復原」：用移除前的預排紀錄重新 `setpreregist`，參數組法與 `changepreregist` 的 previous 相同。
- 復原失敗時顯示原因，並提示到選課網重新加入。

## 錯誤處理

- 沒有開選課網分頁或沒登入：
  - 查詢、移除沿用現有 `cosProblem` 訊息。
  - 課表照本機資料顯示，並在上方標出資料時間。
- 課表沒有任何課時，右欄顯示空課表格線，加一行說明：「還沒有課。在左邊找到課後按『加入預排』，或按上方『從選課網更新狀態』。」
- 移除時選課網回應失敗：不動本機課表，顯示原因。

## 測試

- **單元測試**：`stackWeek`、`hiddenSlots`、`appliedCount`，以及 `removepreregist` 前檢查的判斷函式（拆成純函式）。
- **E2E**（Playwright，模擬選課網）：
  1. 第一次打開面板是開的；關閉後重開頁面仍是關的；Esc 關閉、焦點回到按鈕。
  2. 面板開著時框選時段，左邊結果即時更新；按鈕顯示條件數。
  3. 週一第 3 節放 5 堂預排：該列撐高、5 堂都看得到；同一堂在第 3、4 節位置相同。
  4. 已選上和預排同一格有紅框；全是預排沒有紅框。
  5. 滑過左邊結果：右邊格子標亮、列高不變；週六的課顯示「另有：六 …」。
  6. 點預排的課 → 查詢 → 送出登記（模擬伺服器）；點已選上的課沒有移除鈕。
  7. 從預排移除 → 課表少一堂 → 復原 → 用原參數 setpreregist；模擬課號在 getregist 時拒絕移除、沒有呼叫 deletepreregist。
  8. 窄視窗（800px）上下排。
- 截圖給使用者看：一般狀態、面板打開、同格 5 堂、詳情小卡、窄視窗、深色模式。
